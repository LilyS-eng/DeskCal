# DeskCal Acrylic 对照实验 B：纯 WPF

完全退出日历（托盘 → 退出 DeskCal），解压本包，运行 DeskCal.WpfDiagnostic.exe。空白客户区用于直接观察材质。顶部可以拖动，× 隐藏，右下角 ◢ 可真实改变窗口尺寸。仍使用与 A 组相同的窗口样式、DWM 参数及呈现顺序。实验专用程序不读取日历数据。默认请求 916 × 745 DIP，与上一轮真机初始尺寸对应，按当前工作区裁剪。

请尽量沿用 A 组相同的桌面背景、显示器、缩放、透明效果及电源设置。观察灰色或 Acrylic 后直接按 Ctrl+Alt+上排数字。标记瞬间无需点击窗口；快捷键冲突时可用托盘“Acrylic 诊断”子菜单并在反馈中注明。

1. 冷启动，先不碰窗口。灰色按 1，已是 Acrylic 按 9。
2. 若灰色，按 2，拖右下角 ◢ 稍微改变一次尺寸。恢复 Acrylic 按 3，仍灰按 8。记下在按下、拖动或松开哪个阶段变化。
3. 点 ×，再单击托盘图标展开。灰色按 4，已是 Acrylic 按 9。
4. 若恢复后灰色，按 2，再真实拖动一次。恢复 Acrylic 按 5，仍灰按 8。
5. 托盘 → 退出 DeskCal。回传 %LOCALAPPDATA%\DeskCal\logs 中本次的 acrylic-no-webview2-日期-时间-毫秒-进程号.log。

日志保留主 HWND、子 HWND 枚举、窗口消息、WPF 布局和背景、DWM 属性及返回码。标记处的 browserModules=[] 表示当前进程的已加载程序集和原生模块中没有名称含 WebView2 的项。A 组观察已留档，无需重做。若 B 复现，建立 WebView2 不是复现的必要条件。若 B 多次正常，差异可能与浏览器宿主或其引入的启动、布局及输入时序相关，仍不足以归因到 WebView2 的某个调用。
